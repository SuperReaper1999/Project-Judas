The first task-only final-source verifier used Windows locale-dependent Path.read_text() on UTF-8 metadata. The caf\u00e9 fixture path therefore decoded as caf\u00c3\u00a9 and triggered the exact-set guard. Original source remained untouched; the prerequisite failure was preserved and the mistakenly triggered baseline build was stopped/finished before replacement. The helper now explicitly reads UTF-8, retains the same expected bytes/hashes, and verifies every extracted file before publishing Source. This is a task tooling error, not an engine/archive defect.
