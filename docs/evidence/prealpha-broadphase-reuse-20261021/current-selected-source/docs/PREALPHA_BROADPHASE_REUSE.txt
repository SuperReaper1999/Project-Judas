FINDING

After the support-history correction, the previous event storm is no longer the
dominant steady cost. Fresh sampling of that accepted core identifies repeated
broadphase traversal and pair sorting. During completed-step tags 500–1079 these
account for 33.1% of main-thread CPU instruction samples. These are software
CPU-timer PCs, not hardware cycles, call stacks or GPU time.

Existing-profiler scopes independently show 821 complete candidate passes across
401 selected steps (500–900): 401 prediction/wake passes, 401 ordinary contact
passes and 19 continuous-impact refresh passes. Candidate discovery costs
5.525 ms/step in that instrumented run; the second ordinary pass alone costs
2.680 ms/step. Worker waits and overlapping geometry jobs are not added to these
main-thread costs. No profiler events were dropped or frames truncated.

The final diagnostic reduces these 821 passes to 421: all 401 prediction passes,
19 impact refreshes and the one required ordinary fallback at step 670. Candidate
cost falls to 2.829 ms/step. The guarded second-pass scope averages 0.00665 ms;
it is empty on 400 steps and performs the real fallback on the remaining step.

The first list wakes predicted neighbors. The second follows velocity/force
integration. In this strictly local, callback-free interval, identities,
classification, collision filtering and all other pair-membership inputs cannot
change. Waking affects sleep state, which candidate membership does not read.
Only CoverStepReach can change a tree proxy; its actual reinsertion increments
the existing counter.

CORRECTION AND BOUNDARY

PhysicsWorld::Step records that counter after prediction. If integration has not
changed it, the already sorted candidate list is reused. Otherwise the complete
ordinary traversal runs. This is not cached collision truth: current native
geometry, warm matching, constraints, CCD and event processing still execute.

The certificate must NOT be generalized across callbacks, lifecycle changes or
Step boundaries. The counter is not a universal tree revision: create/destroy
and origin changes use other paths. They cannot occur in this local interval,
and each new Step always generates a fresh first list. Kinematic publication
precedes it; material-coupling callbacks follow ordinary contact generation.

Only src/PhysicsWorld.cpp changes runtime behavior: one local snapshot and one
conditional traversal. There is no new graph, persistent cache, public API,
save format or component. The coordinator remains 872 lines. Actual candidate
work and rejected-layer diagnostic counts legitimately decrease; they describe
executed work, not an invariant physical quantity.

arrays. Across all 900 original steps, 899 certificates hold, one is invalidated
by a real proxy expansion, and zero candidate arrays disagree on certified hits.
The original physical/contact/CCD digests remain unchanged.

The active CandidateReuseTests fixture has 34 checks. It independently enumerates
fat-AABB overlaps and filters, tests mixed body classifications, a real sleeping
neighbor wake, slot generations, filtering, suspension and origin changes between
steps. A real 7,200 N force expands a body's reach to a previously excluded wall;
the fallback discovers that pair and CCD prevents crossing.

The unchanged original core fails only the new one-pass assertion (34 checks,
one failure). An intentionally unsafe always-reuse control fails four assertions:
new wall discovery, collision delivery, physical non-crossing and the required
second pass. The corrected normal build passes all 34. Neither test thresholds
nor the original scene have been weakened.

queries, and exactly the same 5.004293 mm deepest overlap. All recorded states

REMAINING SLOWDOWNS

All-phase smoothness is NOT established. The final live first and busy windows
still have 232/180 ms maximum frame intervals; busy p95 is 75.27 ms. Some impact
bursts therefore remain perceptible despite the much higher average cadence.

The worst first-900 fixed step remains step 153: 140 actual impact events and
12,692 CCD requests, with about 50 ms in the combined solve/impact phase. The
recorded requests and physical outcome are identical to the accepted core.
This change removes the redundant candidate pass, not that remaining event
response/search cost. It does not prove that every remaining request or row is
necessary. Further tail work should profile these exact bursts rather than
reduce counts, cadence or fidelity, or assume an unavoidable hardware limit.

The final instrumented 500–900 window still spends 4.69 ms/step in contact
generation (including the owner's 2.18 ms parallel-geometry batch), 2.90 ms in
continuous impacts and 2.70 ms in velocity constraints. Concurrent worker spans
are excluded from additive cost claims. These are measured remaining stages,
not proof that their entire contents are redundant.

Two isolated alternatives—skipping empty-manifold history lookups and unused
prepared primitive-pose copies—showed only about 1% changes in these runs, without
a demonstrated benefit beyond run/layout variation. Neither is adopted. Their
sources, results and the source-only combined variant remain in the evidence.
Initial geometry already uses workers; this pass does not invent a new threading
implementation or claim the earlier workload had been single threaded.
