PURPOSE
Fix the general collision-shape and query limitations exposed by the skate-game
consumer audit. Imported curved world geometry must not require reconstruction as
hundreds of independent boxes. Scripts must be able to inspect collision geometry
and ask for its closest point without duplicating collider dimensions in game data.

Required scope:
- Cooked STATIC triangle-mesh colliders.
- Cooked convex hull colliders for static and dynamic rigid bodies.
- Compound children with independent local positions AND rotations.
- Practical mesh-to-collider editor/asset workflow.
- Real contact and query integration, including CharacterMotor sweeps.
- Safe public collider inspection and closest-point queries (audit E-04).
- Normal streaming, persistence, export, documentation and integration proof.

Judas owns collision geometry, contacts and physical response.
JavaScript owns skating, grinding and other game behaviour.
This is NOT a replacement physics engine, skateboard system or general CAD suite.

## 2. Collision assets and cooking

Separate immutable cooked geometry from per-instance pose/filter/state. Use the
normal CPU resource/asset pipeline and shared asset lifetimes. Renderer owns GL;
collision cooking and simulation must work without a graphics context.

Provide a documented collision asset format or extend the existing appropriate
asset format. Include format/cooker version, source/settings identity, local bounds,
mesh vertices/indices or convex faces, acceleration data, and feature/subshape keys.

Reuse existing OBJ/glTF CPU import paths for explicit selected source geometry.
Support the static mesh assets needed for the supplied ramps/half-pipes, including
selected primitives and their authored transforms. Do not expand the whole character
importer or silently bake every mesh in a file when the author selected one part.
A separate low-detail physical source must be usable as well as an explicit bake
from a visual model. Materials, render LOD and visibility never change collision.

Cooking must:
- Validate finite coordinates, index ranges, usable areas/volume, winding and bounds.
- Handle duplicate/degenerate triangles deterministically with reported outcomes.
- Build a mesh-local BVH or equivalent midphase, plus physical edge adjacency.
- Maintain a cooked-feature to source-feature mapping where reordering/cleaning occurs.
- State welding tolerances and preserve intentionally separate components/openings.
- Diagnose nonmanifold/ambiguous topology rather than silently claiming welded seams.
- Bound input/output complexity and report any simplification/error policy.

UV/normal seams need not become collision seams. Conversely, close vertices are not
permission to merge distinct nearby sheets. Mesh cleaning, adjacency and feature
remapping are established cooking concerns [R1]; use them deliberately.

Use a mature, suitably licensed hull cooker where useful. Pin any new dependency,
record provenance and ship required notices. Do not write a new asset parser or turn
hull generation into research. Do not import an entire dynamics engine for cooking.

Editor and CLI cooking must share code. Cook into a replacement asset safely: failed
validation preserves the previous accepted asset. Track staleness when source or
settings change. Runtime loads cooked data, not expensive geometry reconstruction on
every launch, spawn or region activation. No silent AABB substitution on cook failure.

## 3. Static triangle meshes: real collision, not just picking

Represent concave authored STATIC surfaces as triangle meshes, not one body per
triangle and not a bounding box with a decorative mesh. Keep the existing world
broadphase, followed by per-mesh candidate traversal and actual geometric narrowphase.

Required contacts include dynamic boxes, spheres, convex hulls and supported compound
children against static meshes. Return contact points, separation and solver normals
through the normal manifold/contact path. Preserve friction/restitution, mass/inertia,
M45 constraints, M42 observations and existing impact processing.

Define sidedness explicitly for contacts and queries. Open meshes are valid surfaces,
not magically watertight solid volumes. Demonstrate front/back behaviour and real
open boundaries. Backface settings must not conceal incorrectly authored winding.
A collider used as a volume sensor must have a supported volume definition; do not
pretend a bare open sheet has an interior. Reject unsupported sensor combinations.

STATIC means no simulated moving concave triangle body in M64. Rigid placement at
creation, editor repositioning and M59 region placement are supported and update
bounds correctly. Runtime replacement/repositioning, if exposed, occurs at safe
boundaries with explicit teleport semantics; it is not continuous platform motion.
Moving shapes use convex hulls or authored convex/primitive compounds.

## 4. Internal edges are an explicit acceptance problem

Replacing boxes with unrelated individual triangles can retain seam artifacts.
Triangle contacts must account for neighbouring physical faces. Do not use smooth
render normals as a substitute for contact geometry.

Implement appropriate shared-edge/internal-feature handling across the cooked mesh:
- A box/sphere/capsule crosses the diagonal of a triangulated plane without a false
  barrier, launch or large contact impulse.
- Concave internal features do not generate artificial blocking normals.
- Actual convex corners, ledges, open boundaries and intentional gaps still collide.
- Coplanar retriangulation does not materially change support/sliding behaviour.
- T-junctions and invalid adjacency have an explicit supported/diagnosed policy.

Use adjacency/feature classification and robust manifold selection rather than
averaging every normal until the demo looks smooth. Box2D's ghost-collision analysis
illustrates the mechanism in 2D [R2]; it is NOT a ready-made 3D implementation.
Jolt's active-edge documentation illustrates the tradeoff between suppressing false
edges and damaging legitimate collision response [R3]. References are prior art,
not permission to restore Jolt as Judas's physics owner.

A triangulated curve remains piecewise planar. M64 need not make a coarse ramp
mathematically smooth or guarantee a perfectly inelastic box conserves energy on it.
Separate geometric faceting, timestep/contact tolerances and artificial seam contacts
in the measurements. Do not promise that all skate assists disappear after importing
a mesh; prove precisely which engine limitation has been removed.

## 5. Convex hulls and oriented compounds

Convex hulls must be actual physical shapes, not query-only decorations. Support
hull-versus-hull, hull-versus-existing primitives/compounds, and hull-versus-static
mesh through Judas's solver. Use an appropriate established convex narrowphase and
bounded degeneracy/convergence handling; retain useful existing primitive fast paths.
An algorithm failure must not silently become a clean miss.

Cook closed convex geometry with usable support/face information. A convex hull of
concave input fills its recesses: show that in the preview and do not claim it matches
the original concave surface. Dynamic concavity uses author-defined compounds; automatic
convex decomposition is not mandatory.

Compute meaningful hull volume, centre of mass and inertia. Preserve the authored
entity pivot through an explicit collider/COM transform rather than moving visuals
or joint anchors accidentally. Verify an off-centre impulse and an analytic fixture;
do not estimate every hull's inertia using its enclosing box and call it exact.

Compound children have stable child keys and local position/rotation. At minimum,
boxes, spheres and convex children must compose correctly. Propagate those transforms
once through contacts, casts, bounds, mass properties, authoring and save/load.
An identity child rotation must reproduce existing compound behaviour. Preserve one
rigid-body identity, not separate independently simulated bodies for each child.
Document mass aggregation for overlapping children; disjoint mass geometry or explicit
mass properties are acceptable, silent double-counting presented as union volume is not.

Keep scale support honest. Bake selected positive nonuniform source scale into geometry
where needed for the supplied assets. Runtime rigid instances may remain unit-scale
if that matches existing contracts. Reject unsupported shear/mirrors/scale clearly;
never render one size while colliding at another. No compulsory general transform rewrite.

## 6. One query contract for real geometry

Extend the existing M39/M44 paths rather than adding mesh-only public casts:
- Raycasts against meshes, hulls and oriented compounds.
- Sphere, capsule and fixed-orientation box casts against those targets.
- Existing overlap/support queries used by CharacterMotor and other consumers.
- Closest-point queries and read-only collider inspection.

Maintain layer/tag filters where applicable, ignored safe handles, disabled state,
sensor inclusion, nearest-hit ordering and deterministic tie-breaking. Broadphase
AABBs are candidates, not final hits. Existing deliberately conservative AABB queries
must remain labelled as such; do not silently change their contract.

Document initial overlap, zero motion/distance, tangency, backfaces, normals and
bounded numerical tolerances. Sweep support is not a universal high-speed CCD claim.
Route new shapes through existing supported impact/continuous paths; explicitly
record any remaining high-angular-speed or unsupported-pair limit.

Results should identify the safe entity/body, collider/child key and mesh feature
where meaningful, plus point, normal, distance/fraction. Explain that cooked feature
keys may change on recooking; they are not immortal cross-version entity identities.
Geometric query normals and edge-aware solver contact normals may differ for a stated
reason, but neither comes from an unrelated rendering normal map.

For closestPoint, specify whether the operation means nearest surface or nearest
occupied point, particularly for points inside closed convex shapes. Expose/describe
containment separately where needed. An open triangle mesh must not fabricate a signed
inside distance. Bound world searches with a maximum radius/filter; use BVH pruning.
If a boundary feature has no unique normal, represent that honestly. Return a clear
no-result for missing/filtered geometry, not stale memory or an invented origin.

Collider inspection returns bounded value metadata: shape type, local pose, dimensions
where applicable, children and cooked-asset identity/counts. No mutable native geometry
pointers or unbounded full-mesh copies on every script read. A generic rail script
must be able to derive an authored box child's extent without a duplicate JS size field.

COMPOSITION
- CharacterMotor on mesh ramps/steps and appropriate slope rejection.
- Nav bake/route through the real mesh opening; audio obstruction through that opening.
- Representative M62 contact and M63 rigid-fragment contact with the new environment.
- Old compounds unchanged; oblique/radial placement and large absolute fixed origin.
- Prefab spawn, region placement, unload/revisit, adoption, handle/asset lifetime.
- Save, close the process, reopen, load and continue physically interacting.
