Rooftop Run consumer reports. Ordinary games should not need to fight support state,
hand-write trigger checks, estimate foot positions from crossfade progress, keep

jumping, grabbing, scoring and other game policy. Keep Judas physics authoritative.

## 3. Fix CharacterMotor support and close the event gap

Addresses Skate B-01 and Rooftop E3/E4/E5.

Reproduce uphill tangent movement on the reported ramp, then correct support departure
semantics. An upward component relative to gravity is not, by itself, separation from
an inclined support. Preserve support for legitimate tangent motion and release it
for actual departure/jumping. Base this on the motor's resolved contact/support and
relative motion, not a scene exception or a blanket supported=true rule. Derive and
test the decision; do not blindly replace one dot product and declare it solved.

Preserve moving/rotating-support point velocity, stepping, slope limits, headroom,
explicit gravity scaling, oblique/radial gravity and genuine loss of support at edges.
Do not add a built-in Jump/WallRun/Skate mode or world-Y fallback.

Document supportNormal precisely: contact/separation normal is not necessarily a
mesh-face normal. Do not smooth legitimate corners into invented walkable surfaces.
Expose a separately named geometric-surface normal only where it is genuinely known;
otherwise report unavailable. Supply a short safe usage example instead of teaching
scripts to project velocity onto every changing contact normal unconditionally.

Integrate motors with the normal M42 event lifecycle:
- A sensor can detect a motor-driven player through ordinary engine geometry/filtering.
- Actual motor contacts and sensor overlaps produce appropriate enter/stay/exit events.
- Use existing M39 masks and generation-safe identities; do not add fake rigid mass.
- Coalesce internal slide/sweep observations into documented fixed-step events, avoiding
  duplicate pairs. Sensors never block or push; missing solved impulse remains null.
- Destroy/disable/resize/teleport, support removal and region unload cannot leave stale
  pairs. Dispatch safely after movement, including callbacks that request destruction.

Document continuous-crossing coverage honestly; do not promise full trigger CCD if
only endpoint overlap is supported. Motor-to-motor physical blocking is NOT required.

Proof: uphill/downhill tangent movement, actual jump, walking off a roof, moving
platform departure, arbitrary orientation, ordinary sensor checkpoints, collisions,
filters and callback destruction. Replace manual checkpoint-box tests in the current
parkour integration copy where available; do not move its checkpoint rules into C++.

## 4. Resolved skeleton access, sockets and minimal IK

Addresses Skate E-01/E-02 and the corresponding bone-selection workflow.

Expose safe read-only joint transforms from the existing resolved pose. Provide clear
local/model/world-space semantics and distinguish simulation/evaluation samples from
presented samples using the engine's actual timing model. Presentation consumers must
see the same pose used for skinning, not raw clip tracks, bind pose or guessed fades.
Missing joints and replaced/unloaded skeleton assets must fail safely.

Add simple authored sockets: a stable joint key plus a local offset/orientation.
Use them for visual attachments and queries without a second skeleton or entity-ID
system. References must remap through prefabs, streaming and saves. A visual socket
must not silently teleport a dynamic rigid body; physical attachment uses normal
joints/forces. Prevent attachment cycles and define evaluation order.

Add one generic two-bone/limb IK contribution with root/middle/end selection, target,
pole/bend reference, weight, enabled state and deterministic ordering. JS supplies
intent/targets; the engine solves the chain through M47 pose composition. Support
moving world targets without humanoid bone-name assumptions. Handle unreachable and
near-straight/folded configurations without NaNs, sudden flips or accidental stretch.
Do not claim an unreachable target was reached.

Preserve clip layers/masks, interrupted crossfades, arbitrary entity orientation and
M48 ragdoll authority. IK must not write directly into GPU matrices or continuously
pose-drive dynamic bones. No full-body IK, balance, motion matching, retargeting,
automatic locomotion or active physical animation.

Proof: a hand/socket prop follows layered/interrupted animation and ragdoll output;
two independently targeted feet follow a tilting board while the rider need not be
rigidly rotated with the entire board. Measure end-target error and inspect in motion.
Explicitly show where the old transitionFraction workaround is no longer necessary.
Persist authored/runtime IK and socket state according to M61's participant contract;
do not serialize cached GPU/layout data or raw handles.

## 5. Sleep idle physics without breaking physical relationships

Addresses Skate F-01; measure the CURRENT implementation before choosing the fix.

Add generic island-aware sleeping/quiescence to the existing PhysicsWorld. Connected
contacts/joints must settle coherently; do not freeze individual limbs that an active
neighbour is trying to move. Use documented bounded motion/error and settling criteria,
not camera distance, object names or a ragdoll-only shortcut. Keep bodies queryable,
visible and available for collisions while asleep.

Wake the affected connected state when something can actually change it: impacts,
forces/impulses/torques, meaningful gravity/support changes, moved kinematic geometry,
motor/limit/attachment changes, collider changes, fracture or external fluid/deformable
loading. Static balanced support under unchanged gravity must still be able to sleep.
Audit each existing force producer so sleeping cannot silently swallow its forces.

Sleeping must preserve appropriate sensor/event behaviour and spatial registration.
Stream/load/destroy safely; restore or reconstruct sleep state without first-frame
explosions, lost support or invalid warm starts. Check bounded wake propagation and
make diagnostic sleep state visible through M56. Keep the existing active solver;
this is not a solver rewrite or permission to lower physics cadence.

Proof: resting crates, one/ten/twenty resting articulations, and a modest fragment
pile; wake by impact/impulse, moving support and changed joint drive. Measure awake
versus settled cost and confirm a sleeping pile can react again. Include one existing
liquid/deformable force interaction to demonstrate it is not ignored. Report residual
cost honestly rather than promising any crowd size is free.

## 6. Complete the small general physics/API gaps

Addresses Skate E-06/E-07/E-09. These are engine access, not game frameworks.

GRAVITY
Expose a public world-position acceleration sample through the SAME normal gravity
resolver used by physics. No CharacterMotor dependency, no assumed -Y and no type
checks in consumer scripts. Prove uniform/radial/overriding regions and a rigid-body
script using the query. Follow existing fixed-origin coordinate conventions.

PHYSICAL MATERIALS
Provide reusable physical-material identity and safe runtime selection/control of
existing friction/restitution properties. Reuse current records where possible; add
only a small normal authored resource if no shared identity exists. Keep physical and
render materials independent. Preserve legacy authored values and existing response
laws. Hits/contact data must identify the actual applicable material where supported;
do not fabricate per-triangle materials when only a body material was assigned.
Changes must wake/invalidate the relevant state safely. No anisotropic friction,
rolling-friction model or new contact-response research.

RUNTIME JOINTS
Expose creation, destruction and re-anchoring/configuration of existing M45 joint
primitives through safe public APIs. Validate first, apply at safe boundaries, invalidate
stale solver caches and reject inconsistent requests without partial mutation. Use
normal entity/ownership references for world anchors and dynamic pairs, including
M59 adoption/unload and M61 reconstruction. No new joint solver, rail or grab system.

Proof: two identical scripts run under different selected gravity; change a body's
physical material and observe the existing response; query the corresponding identity;
create/re-anchor/release an ordinary connection at runtime, then save/reload and unload
its region without stale joints. Preserve the integrated D-01/D-02 regressions.
