GOAL
Add optional additive scene composition and asynchronous region/world streaming.
A running game can retain its player/session while loading, activating and
releasing nearby authored regions. More authored world must not imply that every
region is simultaneously instantiated, simulated or resident in memory.

Judas owns residency, lifetime and safe world composition.
JavaScript owns travel rules, loading-screen policy and game behaviour.

This is content/residency streaming, NOT automatic origin rebasing. M23 remains
fixed double absolute origin + precise local floats. M61 remains the broader
save/persistence milestone. Do not quietly bundle either into M59.

## 1. Extend the actual world lifecycle, not a parallel engine

Trace M43 scene replacement, RuntimeWorld construction/destruction, M29 entity
lifecycle, M31 jobs/resources, script startup/teardown and current component
registration. Identify whole-scene assumptions before changing them.

Additive regions participate in ONE authoritative played RuntimeWorld: shared
physics, gravity resolution, navigation service and ordinary fixed-step ordering.
Keep one played-world scripting runtime, not one VM or simulation per region.
A region is an ownership/lifetime group, not another game loop.

Reuse existing component creation/destruction through a coherent incremental
registration path. Do not squeeze everything through SpawnPrefab if its supported
subset is insufficient, and do not clone RuntimeWorld constructors into a second
streaming implementation. Keep existing single-scene projects working without
having to author a streaming manifest.

M43 replace/reload remains a distinct whole-played-world operation. Define
`scenes.current`, reload and session-store behaviour explicitly: additive loads
must not silently replace the root scene identity or clear session data. A whole
replacement invalidates old region requests and handles. No need to change the
existing replacement API to asynchronous merely for symmetry.

## 2. Authored regions, placement and stable identity

Provide a normal project-owned streaming/world manifest or equivalent asset.
A region has a stable identity, registered source scene, spatial bounds/placement,
load priority, dependencies and residency policy. Reuse `.judas` content and the
existing project registry; no hardcoded directories, numeric scene-name convention
or mandatory terrain generator. Static region placement is sufficient.

Separate authored object identity from runtime entity identity. Different scenes
may contain identical local object IDs. Remap local references for bodies, joints,
prefabs, navigation links and liquid connections consistently; never alias them.
Use generation-aware region/request handles. Reloading a region must not resurrect
an old runtime handle. Loading the same region twice is coalesced/idempotent;
independent copies require distinct declared instance identities.

Use qualified references for cross-region authored links. Unloaded targets are
unresolved, not stale pointers or an invitation to block synchronously. Distinguish
hard dependencies from soft references; detect cycles and group or reject them
with useful diagnostics. Do not rewrite immutable source assets to relocate IDs.

Place all active content in the session's fixed simulation frame. Subtract double
origins BEFORE narrowing coordinates. Preserve arbitrary orientation and transform
all supported spatial components coherently. Require unit scale initially; reject
unsupported placements explicitly rather than moving visuals but not colliders,
gravity, navigation or baked liquids. Do not reset the session origin per region.
Document the demonstrated local precision envelope: streaming does not make
unbounded float-space travel precise. Reuse/validate baked local data under
placement; never suppress stale-bake checks just to make instancing work.

## 3. Genuine asynchronous preparation and bounded installation

Reuse JobSystem and ResourceManager rather than creating another worker pool.
Represent request states clearly, for example:
Unloaded -> Queued -> Preparing -> Prepared -> Installing -> Active -> Unloading.
Include cancellation, failure and blocked-by-dependency/budget states where needed.
Names may differ; expose what is actually happening.

Workers may read, parse, validate and prepare immutable CPU descriptors. They may
not mutate live physics/navigation/liquids, access a live QuickJS context, call GL
or start gameplay. Renderer retains context-thread GPU ownership. Thread-unsafe
parsing/font/asset operations must use the existing safe ownership rules.

Background reading followed by a huge synchronous constructor is NOT sufficient.
Budget incremental main-thread installation, resource handoff AND teardown. Use
bounded work units with configurable time/work budgets. A single native upload,
registration or JS callback may be indivisible: measure the largest such unit,
report overruns and split/preprocess excessive content where appropriate. Do not
promise hard real-time deadlines that these operations cannot meet.

Required physics/geometry and hard dependencies must be ready before a region is
playable. Optional visual-resource placeholders may follow the existing loading
policy, but distinguish CPU-prepared, playable and fully visual-ready states.
Progress is staged work/bytes/counts where known, not a fabricated smooth percent.

Normal frame processing must not WaitAll, poll in a busy loop, or synchronously
fetch unfinished work. Honour cooperative cancellation and discard late completions
using request AND world generations. Cancellation must release only its own demand;
it must not cancel a shared asset still needed by another region.

## 4. Safe activation, unloading and callback order

Perform mutations at a documented safe outer-runtime boundary, never while a
physics query, solver or script/event callback is using the affected structures.
Stage privately and publish a complete validated activation unit. Preparation must
not expose half-built entities, runnable scripts or colliders without dependencies.

Establish identities/references/components before calling script start. Order
activation and callbacks deterministically; I/O completion order must not select
gravity precedence or gameplay singletons. This does not promise identical frame
numbers for nondeterministic disk completion—report activation events explicitly.

Unload prevents new work on the departing group, runs destroy callbacks while the
required services remain valid, invalidates handles and removes registrations at
the safe boundary, then releases resources. Destructive script callbacks may queue
new requests safely. Reuse existing error isolation; do not pretend arbitrary JS
side effects can be transactionally undone after start has executed.

Failed validation/installation leaves the existing world playable and releases
staged demand. Define the no-return point clearly. Test cancellation during each
relevant phase and scene replacement/project close while old work is outstanding.
Pause may allow background preparation; activation/script scheduling must honour
the existing pause contract. Show the actual policy in docs and tests.

## 5. Optional streaming policy and bounded residency

Provide both explicit script requests and an optional generic spatial-interest
policy. Interest sources have authored/runtime positions or bounds, priorities and
prefetch distances. Do not hardcode the player or equate the camera with gameplay
interest. Multiple interest sources must coexist.

Use hysteresis between load/retain/unload thresholds, bounded concurrent requests,
priority and deduplicated demand. Avoid traversing/parsing every scene each frame;
manifest bounds and an appropriate inexpensive spatial index are sufficient.
Use 3D bounds/distances, not world-XZ ground assumptions.

Budget pending CPU data, live region content and shared-resource demand. Report
estimated versus known bytes honestly. Region limits are useful, but not proof of
memory boundedness when individual regions vary in size. Under pressure, evict
eligible low-priority content, defer work or report blocked demand. Never evict
safety-pinned content or discard unique state just to satisfy the counter.

An unloaded region must release real entity/simulation registrations and its asset
references, not merely hide draw calls. Shared textures/materials/fonts stay alive
while still referenced. Bounded caches may retain data under a documented budget;
retained data remains visible in diagnostics, not labelled freed.

## 6. Ownership, travelling entities and session state

Persistent session/root content may remain resident while regions change: player,
HUD, cameras and game coordinator are ordinary project entities, not engine
singletons named Player. Expose generic pin/release and ownership-transfer/adoption
operations sufficient to move a runtime hierarchy between groups safely.

Ownership is distinct from position. A carried crate or travelling agent must not
vanish because the region where it spawned is released. Preserve runtime identity,
velocity and script state when rehoming an active entity. Transfer complete owned
assemblies, or retain external dependencies; do not orphan joints or ragdoll bones.

Retain supports/attachments and required dependency groups while still in use.
Cross-region joints, ongoing link traversal and liquid connections need a defined
pin/grouping policy. Do not sever them silently to make unloading convenient.
Expose pin reasons and lifetime; detect permanently accumulating dependency pins.

Automatic residency eviction is NOT gameplay destruction or round reset. Reuse
existing supported entity/JS snapshot mechanisms for bounded in-session retention.
Demonstrate that one changed/destroyed object does not silently respawn on return.
For state that cannot yet be safely suspended/reconstructed, retain/pin its region
and report the limitation. Do not implement universal VM/physics/liquid snapshots
or a new disk-save format just to claim every region is evictable.

Bound retained session records too; pressure must produce backpressure or an
explicit caller choice, not silent state loss. Report instantiated, cached,
suspended and pinned quantities separately. A documented explicit discard/reload
may reset content, but must never be disguised as ordinary automatic streaming.
Full M43 reload remains the deliberate whole-world reset using its existing rules.

## 7. Compose existing systems without changing their semantics

Make a compact registration/unregistration matrix for current component families.
State which stream incrementally, which are session-owned and which need grouped
residency. Inspect actual M58 output; do not invent its interfaces.

PHYSICS / GRAVITY / MOTORS
Bodies from adjacent regions collide and answer ordinary queries in the same
PhysicsWorld. Contacts, M42 events, joints and support handles clean up safely.
A motor retains its support while needed. Region seams must not imply missing
floors, duplicate overlapping floors or a physics reset.
Gravity uses normal fields/zones, with stable authored precedence independent of
load completion order. Flat platforms still require authored uniform regions;
never derive gravity from the supporting polygon or scene name. Do not let
unloading an in-use gravity dependency abruptly change an actor's field.

NAVIGATION
Register/unregister existing M53 surfaces/tiles through the normal service.
Invalidate affected corridors/links and safely repath or report unavailable
residency; never follow stale native polygon references. Bind cross-region links
only when endpoints are active. An agent waiting for unavailable content does not
teleport or acquire a complete path across absent data. Whole-world route planning
through unloaded geometry is not required. Navigation remains advisory; scripts
choose destinations and CharacterMotor resolves movement.

LIQUIDS / ARTICULATIONS
Preserve M54/M55 quantity ownership and the legacy-fluid guard. Streaming must not
invoke destruction's parked-parcel behaviour and then reload a second copy of the
initial water. Keep a connected liquid group resident while transfers, bodies or
parcels depend on it unless an already-supported lossless suspension path exists.
Pin/report unsupported suspension. Do not split a live surface into independently
simulated sectors or redesign fluid coupling. Ragdoll/joint assemblies similarly
remain complete dependency groups, not independently evicted bones.

RENDERING / AUDIO / TEXT
Shared M57 materials/environment data and M58 fonts/catalogs keep valid resource
lifetimes. Region-local lights, emitters, particles and M33 cameras can register and
leave cleanly. Presentation/interpolation state initializes coherently on activation;
no startup bind-pose flash or fixed/presented camera mismatch.
Session environment/exposure, active view, listener, input map and locale have
explicit ownership/selection. Reject conflicting providers or apply authored
selection; never let the last I/O completion overwrite global state. Do not build
M60 audio features. Preserve localized UI and language selection during streaming.
Per-world module caches remain per-world; document any non-reclaimable cached JS
state rather than claiming a region unload destroyed the whole module environment.

## 11. Focused correctness proofs

Build focused fixtures while implementing; group related assertions rather than
inventing a giant combinatorial validation programme.

- Two additive scenes with colliding authored IDs and local references instantiate
  correctly; real cross-region rigid contact/query proves one simulation world.
- Repeated load of one region coalesces; unload/reload invalidates old handles.
- A real worker read/parse is held by a test gate while ordinary frames continue.
  Releasing the gate uses the actual preparation/installation path, not a fake timer.
- Cancellation before/after preparation, during staged installation and during
  world replacement releases demand and discards late completion safely.
- A malformed/missing dependency leaves the active world intact, without orphaned
  entities/resources. Cyclic dependencies fail or group according to the contract.
- Reversing worker completion order does not alter authored gravity/settings
  precedence. Oblique placement and a huge fixed absolute origin preserve results.
- Active supports, cross-region joints, links, liquid connections and parcels
  prevent unsafe unload. Moving a carried hierarchy preserves identity/motion.
- A changed/destroyed object follows the declared retention policy; bounded cache
  pressure cannot silently reset it. Clean content genuinely unloads and reloads.
- Navigation invalidation/rebinding and script cleanup handle missing neighbours.
  Shared assets survive one consumer unloading and become releasable after the last.
- Rapid travel/reversal exercises hysteresis, priorities and backpressure; repeated
  traversals plateau in live regions, jobs and accounted memory after warmup.
- M58 locale/HUD/capture survives additive changes; M43 full reload/replacement
  still follows its separate contract. Editor Stop restores authored files exactly.
- API/types/examples pass. Moved/read-only export loads a non-startup region from
  an unrelated working directory with no repository fallback.

Deterministic tests may control completion order. Production must remain genuinely
asynchronous; do not substitute the legacy blocking harness for async evidence.
