MECHANISMS AND CORRECTIONS

1. Broadphase pair discovery

The accepted implementation still queried the same tree separately for every
participating body. Each unordered pair was retained once, but overlapping
subtrees were visited repeatedly. A new optional DynamicAabbTree::QueryPairs
traverses pairs of subtrees, partitions their leaf products without duplication,
and marks active ancestors to avoid inactive/inactive work. It returns exactly
the same overlapping fat-proxy pairs. WorldBounds retains current classification,
collision filtering and the canonical sorted output.

PairQueryScratch belongs to the caller. Its marks are refreshed by query epochs,
not saved neighbor memberships. The ordinary Query API and tree mutation/order
are unchanged. The tree object's layout is unchanged; unused trees allocate no
pair scratch. PhysicsWorld reuses its derived scratch and active-proxy vector.
Callbacks may not mutate the tree. Recursive use of one scratch is rejected;
ordinary Query or pair queries with separate scratch can nest safely.

2. Growing-impact discovery

An expanded body queried nearby fat proxies, then prepared the other bodies'
event-time poses/orientations even for many empty pairs. At step 153 the new
existing-enclosure check rejects 14,639 such neighbors before that preparation.
It compares the expanding body's actual event-time bound with the other's
already supported remaining-trajectory enclosure, which contains NOW as well.
Finite disjoint bounds prove no current contact. Inclusive overlap preserves
boundary contacts. Unsupported, uncertain and nonzero-pivot shapes retain the
original path. Tentative solver impulses change velocity at fixed geometry;
a published motion change invalidates the existing remaining-bound cache.

No manifold, response or sampled miss is retained by this check. A copied outer
query avoids aliasing the shared per-body bound scratch. Solver arithmetic,
rows, event chronology, iterations, observations and save formats are unchanged.

CAUSAL AND ADVERSARIAL PROOF

A private diagnostic runs the ORIGINAL per-body tree traversal alongside the
new one: 1,015 exact candidate-array comparisons over 900 unchanged steps,
zero disagreements. Every new rejected pair is also queried through the original
native zero-margin geometry: at least 712,704 audited rejections, no contact or
uncertainty disagreements, and identical physical trajectory digests. These
instrumented runs are correctness evidence, not performance comparisons.

The expanded broadphase fixture checks independent brute AABB overlaps and the
original per-active Query oracle: mixed/empty/all/sparse active sets, duplicate
IDs, closed boundaries, move/destroy/reuse, epoch wrap, callbacks and exceptions.
A deliberately broken mixed-active-pair wrapper produces 17 expected failures.

ImpactDiscoveryTests has 31 checks. Independent native geometry proves actual
contacts at event time, including a moving endpoint whose stored anchor is still
separated. Other cases cover changed trajectories, earlier conservative bounds,
rotation, large translated coordinates, boundary contact, unsupported geometry
and invalid bounds. A real force-driven collision exercises the new rejection
counter without losing the wall response. The stale-storage-bound negative
control fails four checks as intended. Both normal fixtures pass.

One NEW rotating test fixture initially assumed endpoint contact after a bar had
already swung diagonally past the box. The preserved failed fixture/log and its
follow-up identify the actual interior half-time crossing. Existing engine tests,
thresholds and protected fixtures were not modified to hide that authoring error.

An exact-pose manifold-cache probe was rejected before implementation: at the
worst step none of 17,322 incremental pair requests repeated the same represented
geometry. Across 942,639 requests it found only 1,157 potential negative and 32
positive reuses. A cache would add lookup/storage costs to nearly every request.
The earlier rejected full-manifold cache remains preserved in its original report.
The new tree traversal and enclosure check avoid work without caching that truth.

  Original 140 events and 12,692 CCD requests remain identical.
Profiler search/geometry/discovery counters overlap; they must not be added as
independent CPU costs. Root-query counts now describe batched traversals, and
overlapping-leaf counts describe pair endpoints, not old repeated body visits.

The approximately 0.2-second initial catch-up hitch REMAINS. This is a measured
improvement, not all-phase smoothness. The remaining expensive bursts lie in
continuous searches, geometry, contact response and several 60 Hz steps sharing
one render interval. This pass does not prove every remaining query necessary
or establish an unavoidable hardware floor. Relevant next work should isolate
the remaining search and observation-publication costs before another redesign.
There is no camera-specific engine fix or change to timing/backlog policy here.
