## Architecture

- Modding is OFF by default. No discovery, active catalog or mounted subsystem is
  created for an ordinary project or explicit `--no-mods`. Empty opted-in selection
  retains the normal asset/save path.
- A game-authored immutable contract publishes typed references, registry identity,
  addition permissions, exact whole-resource replacement boundaries and revisions,
  data-only behavior property schemas, and bounded extension points.
- `.judasmod` v1 is a bounded uncompressed manifest/inventory/content archive using
  existing checked serialization and SHA-256. Dependencies are explicit; selected
  exact versions resolve deterministically. No best-effort partial set.
- AssetIds are qualified by game/mod/local identity **before** model/terrain cooking
  and nav baking. Base IDs do not change. Independent same filenames/local IDs are
  normal; opaque products and script strings are never patched after cooking.
- One frozen effective AssetDatabase feeds ordinary ResourceManager jobs, QuickJS,
  scene/prefab construction, physics, navigation, regions and save fingerprints.
  Registered virtual scene paths resolve to pinned immutable cache files.
- Inspection/installation compile where required but never evaluate scripts.
  Executable mods need game permission and user trust in the exact SHA-256 payload.
  Trusted project JS has ordinary world capabilities; this is **not a sandbox**.
- Per-game user storage installs immutable versions, uses guarded index/selection
  publication, applies changes at a new session, and refuses in-use removal through
  leases. Unowned unleased cache entries may be reclaimed; base/source/save files
  are never removal targets.
- Strict nonempty save context identifies contract/resolution and every exact
  selected payload. M61 preflight refuses changed/missing selections before swapping
  worlds. Empty/unmodded archive v2 and base fingerprint semantics remain intact;
  only nonempty context uses archive v3. Signals/closures remain transient.

## Authoring and permissions

### Foundation reuse

| Existing foundation | M76 treatment |
| --- | --- |
| Checked binary serialization and SHA-256 | Reused for bounded package inventory/content and exact identity; no compression algorithm. |
| AssetDatabase / ResourceManager / jobs | Extended with one frozen effective catalog; normal resource loading/publication remains shared. |
| M66 cooking, M75 terrain and navigation fingerprints | Reused; owner qualification occurs before cook/bake, with curated read-only references and ordinary writable mod products. |
| M67 author documents / editor transactions | Extended with a manifest draft and local-mod panel; Save, Undo/Redo, external-change guards and terrain tools remain normal workflows. |
| QuickJS / scene, prefab, region and signal lifetime | Reused; declared module imports and a detached public content catalog are added, without another VM or scene constructor. |
| M61 modern save preflight/storage | Extended with exact nonempty mod context; empty/unmodded v2 identities remain unchanged. |
| Exporter / Windows SDK | Extended with explicitly published closure and curated offline guidance, using normal platform tools. |
| Contract, package admission and per-game install store | New bounded policy/resolution/storage layer; these are content machinery, not game rules. |

Curated kits contain explicitly published runtime closure, registry settings,
permitted terrain source, offline guidance/types and an inclusion report. They are
not full private-project copies. A matching editor/tool SDK is a prerequisite;
a mod author does not compile C++.

`judas_mod new` creates an ordinary kit-bound project. The existing M75 viewport
brushes and Create/Fork/Save/Cook workflow remain authoritative. Published kit and
borrowed dependency assets are read-only; writable source/product IDs belong to
the mod. Navigation rebakes against the intended owned collision products.
Editor manifest drafts use normal guarded Save/Undo/Redo/cancel; packaging is an
explicit separate action. CLI/editor/install/runtime share eager validation.

See [support/permission matrix](MODDING.md#format-and-support). v1 excludes owned
world/liquid/deformable/environment/audio-effect/localization-catalog assets and
new numeric registries. Supported cooked models may include baked animation.
Terrain remains finite static M75 height patches, four layers, unit collision
scale, offline navigation and independently authored gravity.

## Validation and limits

See the evidence report for exact executed checks, timings, Windows paths and
fingerprint scope. Linux proof includes real editor sculpt/paint/Cook/bake/package,
actual Application/ResourceManager/QuickJS/physics/nav/region/save behavior, source
unavailability, changed-context refusal and actual exported runtime startup.
The package published by the editor also executes through the real game.

Bounds/transactions and trusted scripts are not security isolation or power-loss
certification. Cold launch admits/validates the whole chosen loadout; it can be
more expensive than steady play. No steady package scanning, recooking or hashing
is added. Installation is synchronous tool work; runtime resources use normal jobs.
Windows retains short-root/long-path limitations and separate hardware acceptance.
No hot mounting, migrations, Workshop, downloads or native plugins.

## Human checklist

1. Launch the lab without mods, then with the isolated selected loadout.
2. Open/export a kit and inspect its inclusion report/offline reference.
3. Open A and B as independent projects. Create or Fork terrain; sculpt/paint,
   Undo/Redo/cancel, Save/Cook and bake navigation before packaging.
4. Install a package, inspect exact identity, explicitly trust executable content,
   enable and restart a moved game. Its base content must remain unchanged.
5. Press 2: walk/jump onto the edited hill, press E and observe the physical prop,
   signal count and ordinary audio. Confirm render/collision match.
6. Press 1 and 4: inspect the permitted landscape/region replacement and revisit.
7. Inspect a denied protected replacement or conflicting pair; no partial loadout.
8. Save, restart and load. Disable a required mod: loading must refuse safely.
9. Use `--no-mods`; selections/files remain intact. Editor Play/Stop preserves source.
10. Repeat applicable steps in the native Windows VM; physical hardware remains pending.
