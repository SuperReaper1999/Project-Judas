# M75 — reusable local terrain authoring (human accepted)

## Capability decisions

| Requirement | Existing foundation | M75 decision |
|---|---|---|
| Planetary terrain | `src/RadialTerrain.*`, `src/TerrainLibrary.*` | Preserve unchanged; this tool creates finite local landscapes. |
| Editable height/paint data | None | Versioned `.judasterrain` source and shared CPU authoring services. |
| Rendering | `src/ModelArchive.*`, `src/ResourceManager.*`, `src/Renderer.*` | Cook ordinary `.judasmodel` geometry and base-color texture. |
| Collision and navigation | `src/CollisionAsset.*`, `src/CollisionGeometry.*`, `src/NavigationAsset.*` | Cook the same indexed triangles; geometry changes invalidate navigation normally. |
| Placement | Rigid transforms, unit-scale collision | Local +Y height axis; arbitrary rigid orientation; gravity remains independently authored. |
| Painting | Ordinary registered textures | Four stable layer identities, normalized weights, local metre tiling; bake base color. No multilayer PBR promise. |
| Editor / CLI | `src/authoring/AuthoringDocument.*`, `src/editor/EditorApplication.*` | Share creation, validation, stroke, mesh and cook services. No external modeling backend. |
| Ownership | Shared immutable runtime products | Explicit shared-source editing; independent forks receive new product identities. |
| Export | `src/AssetDependencies.*`, `src/ProjectExporter.*` | Validate source/dependencies at export; packages consume immutable products. |

## Representation and boundaries

`src/authoring/TerrainAuthoring.*` owns the CPU source/brush/cook services.
`src/editor/TerrainTools.*` is their viewport/panel client; `judas_terrain_author`
is the CLI client. The standalone does not link brush/cook services.

Version-1 `.judasterrain` JSON stores local metre dimensions, sample counts,
heights, four-channel normalized weights, stable layer keys/registered texture IDs,
local metre tiling, output texture size and stable source/product identities.
Grid X/Z spans the centred finite rectangle; height is local +Y, **not gravity**.
Each quad emits `a,c,b / b,c,d`; picking, render mesh and cooked static collision
use these exact triangles. Normals are area-weighted incident triangle normals.
Rendering uses smooth area-averaged vertex normals; collision/query normals are
geometric face normals of those same triangles, not interpolated shading normals.
Terrain is an open, one-sided static surface, without side walls or underside.
It does not supply caves, overhangs, a volume, collision CCD or spherical sculpting.
The existing immutable `RadialTerrain` and planetary gravity remain separate.

Instances use ordinary mesh rendering, base-color texture and M64 triangle-mesh
bodies. Rigid translations/rotations, including the fixed double-origin/local
simulation frame, work normally. Cooked/mixed collision instance scale must be
unit; non-unit/reflected/singular placements are rejected rather than showing a
scaled mesh over an unscaled collider. Primitive-body visual scale is unchanged.
Physical material is independently authored; painted grass does not imply friction.

Four base-color layers are supported; weights blend decoded color in approximate
linear space (gamma 2.2), into an opaque baked TGA. Source images repeat in local
metres. Layer slots/keys stay fixed; the panel adds slots and replaces texture
references, but deliberately offers no silent remove/reorder. Explicit source
remapping must remap weights too. This is not multilayer PBR or transparency.

Bounds: 2..257 samples per axis, at most 65,536 samples and 65,536 triangles
(square editor limit 182); dimensions 0.1..10,000 m; finite heights ±10,000 m;
four layers; each decoded image at most 2048²; baked texture 16..1024². Source
files are bounded to 16 MiB, shallow JSON and 700,000 parse events before DOM
creation. Stroke positions must be inside the finite patch, with at most 4096 scheduled dabs
per input segment; invalid/out-of-bounds segments fail before mutation. Undo and redo each retain at most 64 snapshots and 32 MiB; snapshots
contain heights/weights, not textures. These are admission limits, not a promise
that maximum-resolution painting is instantaneous.

## Editor workflow

1. Open `projects/terrain_lab/terrain_lab.judasproj` in `judas_editor`.
2. Select the terrain, then **View → Terrain sculpt / paint → Edit selected terrain** (opens the source
   and activates the brush). Alternatively choose a new `Imports/*.judasterrain` path and dimensions,
   then **Create new source**.
3. Cook a new source and **Create terrain instance**, select it, enable
   **Enable viewport sculpt / paint** if needed, choose the brush and drag left.
   The yellow footprint follows draft triangles. Misses have no infinite floor.
4. Raise/lower strength is metres per dab. Flatten freezes the press height;
   smooth blends a bounded 3×3 neighbourhood from a per-dab input snapshot.
   Paint strength is a blend fraction per dab. Falloff is `(1-distance/radius)^n`.
   Dabs occur every 0.2 radius of planar local pointer travel, with interpolation;
   stationary hold applies no repeated dose. This is independent of render FPS.
5. One gesture is one undo. Ctrl-Z/Y or panel buttons restore source values.
   Escape cancels the gesture; focus loss commits/ends it. Closing the panel ends
   capture. Middle-pan, right-fly, wheel and frame remain navigation controls.
6. **Save editable source**, then **Cook / publish saved source**. The preview is
   draft graphics, not live physics. No authoring in Play. Unsaved drafts/busy jobs
   block Play/export/project changes/close; save, discard/reopen or cancel and repeat the
   requested action. Saved but uncooked source is rejected by Play/export freshness.
7. Cook completion rescans normal assets. Play walks on the published triangles.
   Stop restores scene state and retains the separate saved terrain source.

Editing a shared source deliberately changes its users. **Fork to the new source
path** creates new source/product identities; cook it and assign/create an independent
instance. Source bytes changed externally cause save rejection, not silent overwrite.
Undo after Save makes the draft dirty without rewriting disk. Geometry preview is
rebuilt once per changed revision; appearance preview is bounded to 256².

## Shared CLI

Commands below use project-relative source for `cook`; other commands use filesystem
paths. Run from the repository, or use absolute executable/project/source paths.

```sh
build/judas_terrain_author create /tmp/patch.judasterrain 65 65 64 64
build/judas_terrain_author validate /tmp/patch.judasterrain
build/judas_terrain_author brush /tmp/patch.judasterrain raise 0 0 0 6 1
build/judas_terrain_author brush /tmp/patch.judasterrain flatten 4 2 0 3 0.5
build/judas_terrain_author fork /tmp/patch.judasterrain /tmp/independent.judasterrain
build/judas_terrain_author cook projects/terrain_lab/terrain_lab.judasproj Imports/landscape.judasterrain
build/judas_navigation_bake projects/terrain_lab/terrain_lab.judasproj Scenes/landscape.judas
build/judas_export projects/terrain_lab/terrain_lab.judasproj /tmp/TerrainLab
```

`create` optionally accepts a project-relative product directory after the dimensions
(e.g. `Content/Terrain/my-patch` for a project using `Content`). The editor uses the
configured asset folder automatically; forks preserve its parent directory convention.
Cooking rejects products outside the configured asset discovery root.

Move editable source into the owning project before cooking. Texture references
must be registered there. The lab source already contains the hill/depression/pad,
smoothed transition and painted stone path; reopen it to continue editing.

## Cooking, ownership and consumption

A guarded cook captures source, texture bytes and texture registration metadata;
source contains settings and the receipt pins cooker revision `M75-1`. It emits
ordinary model/texture/collision assets with sidecars and a hash receipt. Outputs
are staged/rolled back by the existing authoring publisher. Cancellation or changed
inputs/products retain last-good output. Publication is per-file rollback-capable,
not a claim of filesystem-wide crash atomicity. Jobs receive immutable CPU snapshots;
only the editor/resource owner creates GPU objects. Project shutdown cancels/waits.

Painting weights/tiling only updates appearance/receipt, retaining exact model/collider bytes.
Changing the palette texture identities changes model dependency metadata and currently
requires collision/nav freshness refresh, even if vertex positions do not change.
Normal asset geometry fingerprints invalidate old navigation after sculpting;
paint alone leaves geometry/nav current. Offline Recast bakes and Detour queries
use the same cooked triangles. No runtime nav rebaking is added.

Playback requires ordinary cooked assets, not source, receipts or editor services.
Export validates freshness and gathers model/collision/appearance plus declared
layer texture dependencies through normal all-assets/closure policies; no JS-string
reachability guessing. Modern saves reference immutable content and normal body/
motor state. Changed/missing required terrain must fail before live-world replacement.
Region active/unload/revisit uses existing collision readiness and safe lifetime.

Future local authoring tools can call creation/validation, `TerrainDraft`, geometry,
painting and `CookTerrain` directly. M75 supplies no mod importer, permissions,
overrides, scripting sandbox or runtime editing API.

WASD move; mouse look; Space script-driven jump; E drop a physical sphere;
F1 normal / F2 oblique terrain; R reload; F6/F7 modern save/load; Escape pause.

## Necessary generic corrections

Useful terrain exposed an inherited CharacterMotor capsule overlap adapter that
passed infinite range to cooked triangle geometry at every sampled sweep/refinement.
The sampler only consumes overlap (`distance <= 0`); passing that exact zero range
allows the existing BVH to cull triangles outside the capsule AABB. The 65² fixture
now examines 48 triangles through 143 BVH nodes instead of repeatedly scanning all
8192 faces. Collision responses, substeps, cadence and terrain quality are unchanged.
This applies to ordinary cooked meshes, not terrain/scene names.

The previously documented unit-scale cooked/mixed collision placement contract is
now checked by scene loading, runtime creation/prefab preflight and transform updates.
Previously a scaled visual could coexist with an unscaled collider. Authors must
bake scale into geometry rather than relying on that mismatch.

## Reuse and derived content

The lab also includes a neutral 12×12 m patch (`Imports/neutral.judasterrain`)
with independent source/product IDs beside the 64 m landscape. Shared edits cannot
change that control. The lab provides a normal terrain prefab (`Assets/prefabs/terrain_patch.judasprefab`)
and an additive annex at local X=96 m; neither owns mutable terrain buffers.
The rotated scene uses oblique placement and a fixed absolute origin of
(10¹², −2×10¹², 3×10¹²) m. It is still a finite patch, not a spherical sculptor.
Flat and rotated navigation assets are normal offline bakes. After sculpting,
rebake them using the normal navigation tool/panel before export; stale navigation
is correctly rejected. Layer references are declared export dependencies even though
playback uses the baked color image. Authoring source and receipts are not packaged.

The second-project proof transfers editable source and registered textures, forks
identity, edits through the shared CLI and actual editor, cooks/rebakes/exports, then
runs from an unrelated directory while its source project is hidden. M76 can reuse
`TerrainDraft`, `CreateTerrain`/`ForkTerrain`, geometry/texture preparation and
`CookTerrain`. No mod loader, permissions, overrides or runtime brush API exists.

## Practical work bounds and limitations

Brushes touch bounded grid rectangles; smoothing snapshots the height grid per dab.
Geometry preview recomputes the bounded full mesh/normals when geometry revision
changes. Painting updates preview appearance without rebuilding mesh. Publication
is whole-product cooking at these scene sizes, with byte comparison preserving exact
unchanged model/collision outputs. No runtime regeneration or steady uploads occur.
Maximum mesh geometry is bounded below 4.25 MiB of vertices/indices before archive/collision
metadata; maximum baked RGBA is 4 MiB. Up to four decoded 2048² images require
64 MiB transient pixels, plus bounded source/DOM/history/cooking staging. These are
bounds/estimates, not a complete allocator census.

Only unit-scale static open triangle surfaces are supported; patch edges have no
side walls/underside, and steep/self-intersecting authored height changes are not a
solid-volume terrain solver. Palette slots are stable, with no interactive removal/
reordering. Only base color is layered; friction and other materials stay separate.
There is no automatic seam stitching, LOD, erosion, spherical editing, water coupling
bake or Play-time editing. Physical Windows GPU/input acceptance remains outstanding; the operator accepted
Linux brush feel and the M75 workflow on 2026-10-10. M74 human review and M67 deferred review remain outstanding.
