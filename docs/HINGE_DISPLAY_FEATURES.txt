INDEPENDENT FINDINGS
Both requested gaps are confirmed. Desktop windows were already manually
resizable, but startup always requested 1024x768 and the deterministic harness
had no resize command. The Android packager omitted an orientation policy.
Hinge genuinely adapts its UI reference size from world.viewport and toggles a
portrait warning; its original zip and game source have not been changed.
Hinge.zip SHA256: 46cb452ac6dd1bca5724be37b4582d5251db862cf2b00e1dce20c41b7e0a0c22

A further dependency was verified in pinned SDL 2.32.10: native window creation
calls SDLActivity.setOrientationBis, which sets FULL_USER for our resizable
window with no orientation hint. Merely adding a manifest attribute would be
incomplete: SDL would overwrite it. The new JudasActivity override preserves an
explicit manifest policy; an omitted policy delegates to SDL as before. Metadata
lookup failure is explicit, not a silently unrestricted orientation fallback.

IMPLEMENTATION
#23: tools/build_android.py --orientation accepts any (default), landscape,
portrait, sensorLandscape and sensorPortrait. The actual manifest generator sets
screenOrientation, and the APK .build.json receipt records the selected policy.
This is a build option, not a new .judasproj setting. Keep it in the project's
repeatable build command. No native Android physics/gameplay change is needed.

#24: JUDAS_WINDOW_SIZE=WIDTHxHEIGHT selects desktop startup size. Default1024x768
is unchanged; malformed values fail before window initialization. RESIZE w h
frame runs before that frame's input/UI/gameplay; EXPECT_VIEWPORT checks both
window and published gameplay dimensions. Bounds are 1..8192 per dimension.
Android surface dimensions remain platform-owned and reject desktop RESIZE.
Window::Resize pumps native window updates without routing real devices into
the deterministic input snapshots.

A related genuine capture defect was corrected: CaptureFrame previously read
RGB rows with the caller's pack alignment into a tightly sized buffer. Odd
widths could produce incorrect rows and overwrite the buffer. It now uses
alignment1 for readback and restores the prior GL packing state. Regression
coverage checks the whole odd-width image and preservation of alignment8.
No public JudasJS bindings, physics semantics or gameplay rules were changed.

TEST-ENVIRONMENT FINDING / PRESERVED FAILURES
The first restricted desktop runs silently selected SDL's offscreen video
backend. That backend reports resized logical/drawable dimensions while its
EGL backing buffer retains the startup size. Dimension assertions passed but
Hinge screenshots were cropped. Pumping events, making the context current and
swapping did not fix that backend. A small native GL pixel probe established the
cause: offscreen reads black outside the old buffer; real X11 reads the cleared
colour throughout the resized buffer. The discarded make-current/swap changes
are not in the final implementation. Window::Resize now explicitly rejects
'offscreen' with instructions to use a desktop backend/Xvfb or startup-size runs.
This is a declared backend limitation, not a hidden headless pass.

An initial baseline run also lacked a writable sandbox save directory. Retried
with an isolated XDG_DATA_HOME, without changing Hinge or engine save policy.
An initial AAPT assertion expected hexadecimal XML dump values; actual SDK output
uses decimal enum values. Only that diagnostic assertion was corrected.
Exporter initially rejected mismatched runtime/exporter source fingerprints after
Android integration edits. Matching tools were rebuilt; the successful export
followed that rebuild. The rejection is preserved as a useful negative control.
