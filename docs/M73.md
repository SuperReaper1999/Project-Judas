## Ownership and scheduler design

`ScriptSystem::Impl` lazily owns one transient signal store per played VM/world.
Subscriptions identify entity, script slot, **runtime instance generation**, channel
and lane. Indexes cover channel, channel+target entity and owner; emission never
enumerates the world's entities. Zero-use worlds allocate no store. Helpers inherit
the active callback's ownership; constructors/module evaluation cannot publish.

FIXED drains once in `StepPlayedWorld`, after physics/motor/pose/contact/fracture
publication and before outer replacement. UI drains once in `InteractivePlay::Frame`,
after UI callbacks/input, before pointer reconciliation and gameplay. It also runs
with no UI document, while paused and on zero-step frames. Modal ownership is checked
again after the drain. Existing input consumption and closing-frame suppression stay
in place. Fixed deltas are the normal fixed interval; UI deltas are outer-frame time.

Matching token identities are frozen on acceptance, sorted by entity ID, authored
slot order, then token. Each drain detaches its eligible FIFO batch. Newly emitted
messages cannot extend it. Deferred work goes before new emissions. At most 256
recipient attempts execute per lane per boundary; several fixed steps in one frame
are several eligible drains. Physics integrates once; signal intent affects later
steps. No Promise pumping, recursion, timer service or elapsed-time quality policy.

A token is a disposable world-prefixed string; one slot cannot unsubscribe another.
Duplicate slot/name/phase subscribe returns the same token. Retiring/faulting slots
remove indexed ownership without relying on destroy. Queued native identities do
not hold JS closures/entities. Delivery rechecks the actual enabled slot and instance
generation; replacement/suspension cannot inherit an old reservation. Emitter death
does not cancel an accepted notification; its safe wrapper can be null at delivery.
Compatible instance adoption keeps the token. Streaming shares this service/VM.

Payloads are descriptor-traversed bounded JSON data. Proxies/accessors/functions,
cycles, nonfinite values, unsupported prototypes, native wrappers, sparse arrays
and extra array properties are rejected. No getters/toJSON are invoked. Serialized
bytes are captured once; each handler gets a separately parsed copy. A handler
uses the ordinary interrupt/error/asset-attribution path. Its fault retires its own
subscriptions and other recipients continue. Internal lifetime cleanup and native
routing are not additional gameplay callbacks.

## Hard limits

- Exact UTF-8 channel names: 1–128 bytes, no NUL.
- 32 subscriptions per slot; 2048 per world.
- Payload: 16 KiB serialized, depth 8, 1024 values/properties; plain arrays/objects.
- Fan-out: 256 matching live recipients per emission.
- Both lanes together: 256 queued events, 1 MiB accounted bytes, 4096 recipients.
- 256 recipient attempts per lane per drain. Queued-byte accounting includes payload,
  channel, fixed envelope allowance and recipient IDs; it is not total allocator RSS.

Over-capacity acceptance throws atomically. No listener returns zero/null sequence
and queues nothing. Acceptance count does not guarantee recipients survive.
`signals.stats` exposes current storage counts and accepted/delivered/skipped/rejected
counters. Cancellation and cleanup release reservations; deferred batches remain
bounded by the same combined capacities.

## Save boundary and limits

Signals are transient. M61 save capture neither flushes queues nor persists tokens,
subscriptions, payloads or delivery cursors. `state`/session store game facts;
`start` and `restore` register via a shared helper without resetting restored facts.
Fresh worlds/processes have empty queues. Required intent must be stored explicitly;
accepted undelivered signals are not durable. No save schema or participant changes.
No cross-world/project/process/network routing, wildcard channels, schema assets,
request/reply or automatic rebroadcast of engine observations.

Judas owns bounded routing and lifetime. Project JS owns names, payload meaning,
responses and incremental adoption. Existing projects need not use this primitive.
See [reference](judasjs/signals.md), [lab](../projects/signals_lab/README.md) and
`docs/evidence/m73/` for executed checks and final source identity.

`.cache/judas-promo` path remains a compatibility symlink; the user's Videos delivery
also remains intact. Original game/engine files were not modified for the showcase.
